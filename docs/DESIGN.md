# Офисная Дота — дизайн-документ

## 1. Что это

MOBA для офисной LAN. Концепт Dota 2: карта, три линии, лес, башни, крипы, трон,
экономика, герои, скиллы, предметы. Тема — офис. Темп — Turbo.

Ключевое ограничение, из которого растёт всё остальное: **состав игроков нестабилен**.
Люди приходят, уходят, их дёргают на созвон. Игра обязана это переживать без потери фана.

## 2. Целевые параметры

| Параметр | Значение |
|---|---|
| Игроков в команде | 1–3, **динамически** (может меняться по ходу матча) |
| Длина матча | 12–20 мин (Turbo-темп) |
| Сервер | один `.py` на чьём-то рабочем компе, остальные заходят по `http://<ip>:8888` |
| Клиент | Firefox 143+, Canvas2D, **ноль внешних зависимостей** (в сети нет интернета) |
| Бэкенд | Python 3.11 + Tornado, единственная зависимость |

## 3. Нестабильность состава: решение

Порядок приоритетов — **пауза важнее ботов**. Мы все свои, мы подождём.

1. **Дисконнект → авто-пауза немедленно.** Матч замирает на том же тике.
   Все видят: «Ждём Васю — 2:14».
2. **Реконнект по устойчивому `player_id`** (localStorage). Вася открывает вкладку,
   автоматически забирает своего героя, идёт обратный отсчёт 3‑2‑1, матч продолжается.
3. **«Играть без него»** — любой игрок может проголосовать за продолжение.
   Герой уходит под управление бота. Если Вася вернётся — заберёт героя обратно у бота.
4. **Ручная пауза** — любой игрок, в любой момент, без «банка паузы». Все свои.
5. **Заморозка матча** — если разошлись совсем, состояние пишется на диск.
   Можно доиграть после обеда или завтра.
6. **Подключение посреди матча** — новый игрок берёт бота своей команды
   или создаёт нового героя (с компенсацией уровня/золота до среднего по команде).

## 4. Экономика реагирует на численность

Проблема: 3v1 при обычной доте — это мгновенный снежный ком и конец игры.

Две независимые крутилки:

**а) Сублинейный доход команды.** Суммарный доход команды от крипов растёт медленнее,
чем её численность. Третий игрок приносит команде меньше прироста, чем второй.
```
team_income_multiplier = N ** 0.75 / N        # N = число героев в команде
```
Так численный перевес остаётся преимуществом, но не автопобедой.

**б) Компенсация за неравенство.** Отстающая по «эффективной силе» команда получает
множитель к золоту и опыту.
```
effective_power(team) = Σ по героям: 1.0 если человек, 0.6 если бот
underdog_mult = clamp((enemy_power / own_power) ** 0.65, 1.0, 2.2)
```
Бот считается за 0.6 человека — это признание факта, что бот играет хуже.

Обе крутилки вынесены в конфиг и выключаются одним флагом, если окажется, что
«офисный гандикап» бесит больше, чем помогает.

## 5. Сетевая модель

**Сервер-авторитетный, фиксированный тик. Никакого клиентского предсказания.**

- Симуляция: 20 Гц, фиксированный `dt = 0.05`
- Снапшоты клиенту: 15 Гц, только видимое команде (туман войны = и античит, и трафик)
- Клиент шлёт **интенты** («идти в точку», «каст в точку», «купить предмет»), не позиции
- Клиент интерполирует между снапшотами с буфером ~100 мс

Обоснование отказа от предсказания: в LAN пинг 1–3 мс, а управление в MOBA — командное
(клик-ту-мув), не непрерывное. Предсказание дало бы нулевой выигрыш в ощущениях
и утроило бы сложность нетворкинга. Если когда-нибудь понадобится играть через интернет —
добавим тогда, архитектура это позволяет.

Формат: JSON. В LAN трафик не проблема, зато всё читаемо в отладке.

## 7. Что осознанно НЕ делаем

Честно о границах, чтобы не было сюрпризов:

- Нет курьера как юнита. Покупка доступна откуда угодно, доставка 12 с (на базе — мгновенно).
- Нет высоты рельефа и связанного с ней промаха. Есть только стены и деревья.
- Нет денаев крипов на старте — вернём, если окажется, что без них скучно.
- Нет пула из 120 героев. 6–8 хорошо проработанных архетипов лучше, чем 30 сырых.
- Нет матчмейкинга и рейтинга. Это офис, а не рейтинговая лестница.
